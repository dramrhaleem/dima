# خطة تنفيذ B1

النطاق: حساب حقيقي محلي، مصادقة OTP وتهيئة Google، ملف خاص وصلاحيات وshell متجاوب. لا مكتبة أو مؤقت أو روم فعلية قبل مراحلها. لا نشر. تفويض لاحق من المستخدم غطى إعداد Google OAuth وقبول سياسته المحددة وإنشاء عميل ديمة؛ تم داخل مشروع قائم بسبب حد إنشاء المشاريع.

## مسارات العمل

1. المصادقة: Supabase SSR بجلسة cookie على الخادم، OTP مع صندوق SMTP محلي، Google PKCE عند تهيئة المزود، رجوع آمن للرابط الداخلي، تجديد وخروج وعزل الحسابات.
2. البيانات: ملف خاص بالاسم/timezone/النية/المظهر/الحركة، أدوار يضبطها الخادم، فصل الملف العام، RLS، حفظ ذري بإصدار وoperationId، منع تزوير المالك أو الدور وتعارض جهازين.
3. الواجهة: Auth وOnboarding قابل للاستئناف وToday بحسب النية وSettings، shell هاتف وكمبيوتر، حالات التحميل/الفراغ/الفشل/الحفظ/تعارض الإصدار. روابط اللاندنج الحالية تدخل الرحلة الفعلية دون إعادة تصميم.
4. التكامل: migrations قابلة للتكرار بلا مسح بيانات B0، روابط API موثقة، اختبارات حسابين وbrowser contexts مستقلين، رسائل OTP حقيقية إلى صندوق اختبار محلي، build Workers وقراءة بصرية ومراجعة مستقلة.

## حدود التحقق

- لا مصادقة بكلمة مرور في واجهة B1؛ اختبار B0 يبقى معزولًا في /dev/foundation.
- Google غير مفعّل دون إعداد ديمة الخاص؛ وجود الكود ليس نجاح OAuth فعليًا. فشل/إلغاء callback يختبران محليًا. إرسال البريد العام وGoogle المستضاف وCPU يبقون بنود نشر غير مثبتة.
- Shell لا يحوي إحصاءات أو إنجازات وهمية؛ المواضع اللاحقة موسومة بوضوح.
- AC01 العودة للرابط، AC03 عدم تسرب الحساب، AC04 عزل الملف المتاح؛ AC02 Work-only دون كورس فقط، وبدء جلسة في B4.
- تحقق TypeScript/lint/tests/build، اختبارات قواعد البيانات وAPI، ورحلات متصفح على 320/375/1280 مع الكيبورد والحركة المخفضة. لا يُدّعى امتثال وصول شامل من smoke checks.
