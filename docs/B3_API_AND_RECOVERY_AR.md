# B3 — العمل الجزئي والاستدراك

امتداد محلي لعقد [B2](B2_API_AND_LEARNING_AR.md)، على `GET/POST /api/v1/learning` نفسه. لا endpoint يسمح باستبدال حالة الحساب من العميل. كل كتابة تخضع لهوية الحساب، `expectedRevision`، `operationId` ومعاملة قاعدة بيانات ذرية. الرد المكرر يعيد أحدث حالة مع هوية المعاينة الأصلية.

## الحالة

- `dataVersion: 3` مع قراءة B2 القائمة دون reset. الإنجازات السابقة لا تُنشئ جهدًا؛ الإنجازات الجديدة القديمة تُحوّل إلى أحداث بمعرّفات ثابتة عند القراءة/الكتابة التالية.
- `workEvents`: وقت UTC وسياق اليوم والمنطقة الزمنية الأصليان، مصدر العمل المستقل أو الإكمال، الجهد الأصلي والمصحح، المتبقي المعلن، وإبطال الحدث دون حذفه.
- `remaining`: تقدير منفصل لكل نشاط؛ `null` يعني مجهولًا ولا يستبدل تلقائيًا بالتقدير الأول.
- `controls`: احتياطي، استثناءات أيام، أولويات كورسات، مثبتات وتوقفات مؤقتة. `previousSettings` يحتفظ بالإعدادات المطلوبة لمعاينة التراجع، ولا يستعيد نسخة قديمة من الإنجاز.
- `planningRevision`: تغير مدخلات التخطيط فقط؛ تسجيل العمل أو تغيير المتبقي ينبه لمراجعة الخطة، بينما ترتيب اليوم أو فتح معاينة لا يصنعان تعارضًا وهميًا.
- `todayOrder`: ترتيب اليوم فقط. `missedStudyDays`: سجل محدود للأيام الفائتة؛ منفصل عن الأعمال المتأخرة الحالية حتى لا يصبح تعثر قديم تنبيهًا دائمًا.

## الأوامر المضافة

| الأمر | الأثر |
|---|---|
| `worked` | يسجل العمل الحقيقي والمتبقي المؤكد/المجهول دون إكمال النشاط؛ يمكن تسجيل عمل قبل اكتمال المتطلبات مع تنبيه |
| `setRemaining` | يصحح المتبقي دون اختلاق عمل أو ساعات مؤقت |
| `resolveWorkEffort` | يؤكد جهد حدث كان مجهولًا مع حفظ القيمة الأصلية وسياق التاريخ |
| `voidWork` | يبطل إدخال عمل مستقل أُدخل بالخطأ؛ يطلب مراجعة المتبقي |
| `reopen` | يعيد فتح نشاط مع الاحتفاظ بالعمل الحقيقي ومتبقٍ يحدده المستخدم |
| `laterToday` | يؤخر ترتيب النشاط داخل اليوم دون تغيير السعة أو التواريخ |
| `undoRecovery` | ينشئ معاينة جديدة بالإعدادات السابقة والتقدم الحالي |

`complete` و`undo` يحتفظان بالفصل بين ادعاء الإكمال والعمل الناتج منه. التراجع عن إكمال خاطئ يبطل الحدث المشتق المرتبط فقط؛ لا يمس العمل المستقل. الإكمال يظل مشروطًا بالمتطلبات السابقة. أحداث الإكمال تحفظ أيضًا تغطية المثبتات كحالة تراكمية، حتى لا تعود حجزًا جديدًا عند إعادة الفتح مع الاحتفاظ بالعمل. حل جهد قديم مجهول لا يخصم المثبت مرة أخرى؛ التراجع يبطل تغطية حدث الإكمال المقصود فقط.

العمل المرتبط بمثبت يحتاج اختيارًا صريحًا ومثبتًا لنفس النشاط واليوم والمنطقة الزمنية، ويُخصم مرة واحدة.

## قواعد المعاينة والتطبيق

السعة مشتركة بين الكورسات. الاستثناء يستبدل سعة اليوم؛ الراحة صفر؛ التوقف لا يُعد تعثرًا. يُستخدم الاحتياطي باختيار صريح، دون زيادة السقف اليومي. الموعد المستهدف منفصل عن المتوقع، وكل متبقٍ يظهر موزعًا أو غير موزع أو مستبعدًا بسبب التوقف.

المعاينة تعرض الخطة السابقة والجديدة، تغير أيام الأنشطة، الجهد المقبول، الحمل والاحتياطي والهدف والتوقع والأسباب. تعارض المثبتات يمنع التطبيق. توزيع جزء من العمل يحتاج إقرارًا بالباقي؛ المعاينة التي لا توزع شيئًا وبها عجز لا تُطبق. التوقف الكامل الصريح قابل للحفظ ويظهر كتوقف.

تُرفض المعاينة عند تغير الحالة أو إعدادات الحساب أو اليوم أو المنطقة الزمنية أو انتهاء 24 ساعة، وكذلك المعاينات ذات سياسة مختلفة عن `PLANNER_VERSION` الحالية؛ الفحص موجود في الواجهة والخادم. تعديل المنطقة الزمنية لا يعيد كتابة تاريخ الأحداث؛ احتساب سعة اليوم الحالي يستخدم وقتها UTC في المنطقة الحالية لمنع استهلاك السعة مرتين.
