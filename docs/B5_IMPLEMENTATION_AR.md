# B5 — الغرف والجلسات الجماعية

الحالة: التنفيذ جارٍ، ولم تُغلق بوابة القبول. المرجع: [مواصفات الغرف](ROOMS_AND_FOCUS_SPEC_AR.md)، [ترتيب التنفيذ](WEB_WATERFALL_AR.md)، [مراجعة B5](evidence/B5_REVIEW.md).

## الناتج المطلوب

دليل غرف عام، وغرف صامتة مرتبطة بموضوع أو كورس معتمد، وحضور خاص بالأعضاء الحاليين، وجولات بومودورو متزامنة. دخول الغرفة يبدأ بالمشاهدة؛ احتساب الوقت يتطلب اختيار المشاركة في الجولة الحالية. كل جولة لاحقة تحتاج اختيارًا جديدًا. تُستخدم جلسات B4 وفتراتها وإيصالاتها نفسها؛ لا يُنشأ سجل وقت موازٍ.

## خطوات التنفيذ وبواباتها

1. تثبيت العقود والسياسات وقواعد القفل، ثم مراجعتها قبل SQL: حساب ← غرف مرتبة ← دورات مرتبة ← كيان/مهمة. لا يبدأ الانتقال قبل فحص المقصد بالكامل. الإزالة الإدارية تثبت نقطة قطع تحت قفل الغرفة، ويطبقها كل مسار قراءة/تسوية فورًا.
2. إضافة مخطط وقواعد وصول وتحديثات ذرية: غرفة، عضوية، دورة ثابتة، مشاركة في جولة، وتقارير/حظر بالحد الأدنى اللازم للغرف. هجرتا B4 المطبقتان تبقيان دون تعديل. مراجعة مستقلة ثم نسخة احتياطية ثم تطبيق إضافي.
3. تشغيل Supabase Realtime الرسمي محليًا، بقنوات خاصة وإشارات تحديث محدودة بعد نجاح المعاملة. رمز قصير العمر لقراءة قناة واحدة، بدون `sub`، ولا صلاحيات حساب أو كتابة بث. لا يُرسل الاسم أو المهمة أو تفاصيل الوقت في البث. اختبار المنع والإلغاء وانتهاء الصلاحية فعليًا.
4. ربط الواجهات: الدليل ← تفاصيل عامة ← تسجيل الدخول مع حفظ المقصد ← موافقة ظهور الاسم والحالة ← مشاهدة ← مشاركة صريحة ← وقتي/تحكم B4 ← استراحة ← مشاركة صريحة لاحقة. شريط الجلسة الحالي يستمر بين الصفحات. لا إعادة تحميل كاملة عند العودة إلى التاب.
5. اختبارات API والتزامن والخصوصية، ثم اختبار المتصفح والمراجعة البصرية وإمكانية الوصول. معالجة أعطال هذه المرحلة ثم إعادة التحقق المتأثر قبل إغلاقها.
6. اختبار حمل محلي: 100 اتصال لمدة ساعتين، أولًا 4 غرف × 20 عضوًا + 20 تابًا ثانويًا، ثم توزيع متنوع. قياس الاتصالات والتأخير والتسليم والموارد وفشل/استعادة الاتصال. الاختبار القصير لا يستبدل هذه البوابة، والدليل المحلي لا يثبت حدود الخدمة المستضافة.

## السلوك الحاسم

- 20 مقعدًا تشمل المضيف؛ حجز المقعد ينتهي بعد 180 ثانية بلا تجديد. انتهاء المقعد يلغي الاطلاع على قائمة الأعضاء، ولا يلغي الوقت المحدود الذي قُبل سابقًا. الاستكمال يحتاج عودة صريحة؛ الإيقاف والإنهاء الشخصي يبقيان متاحين.
- تجديد واحد كل 30 ثانية للحضور والتحكم المطابق في الوقت. التجديد العادي لا ينشئ إيصالًا دائمًا ولا يبث لكل الأعضاء.
- الدورة 4 فترات تركيز، بينها 3 استراحات قصيرة ثم استراحة طويلة. لا دورة جديدة ولا مشاركة جديدة تلقائية.
- إعدادا 25/5/15 و50/10/20. ساعة الغرفة يحددها الخادم، ووقتي الشخصي ظاهر مستقلًا عنها.
- إنشاء غرفة جديدة لا ينهي جلسة أو عضوية قائمة ضمنيًا. الموافقة على ظهور الاسم والحالة منفصلة وواضحة.
- انتقال التحكم بين الأجهزة لا يكرر احتساب الوقت. كل قراءة خاصة تعيد فحص العضوية والصلاحية؛ الرد المتأخر بعد الخروج أو تغيير الحساب لا يعيد بيانات قديمة.
- انتهاء الغرفة بلطف ينتظر الدورة الحالية؛ التعليق الإداري يقطع الوصول فورًا. المطالبة بالاستضافة بعد 120 ثانية غياب، ونقل الاستضافة بعرض وقبول صريحين.
- لا محادثة أو كاميرا. التفاعلات المحدودة أثناء الاستراحة فقط. البيانات التفصيلية والخطط لا تظهر للآخرين.

## توزيع التنفيذ وحدوده

العقود وقاعدة البيانات وAPI لدى عامل الخلفية؛ الواجهات ودورة حياتها واختبار المتصفح لدى عامل الواجهة؛ مراجعة مستقلة لدى عامل المراجعة. التكامل والبنية المحلية والبث والتوقيع والأدلة النهائية لدى المنسق. البناء وإعادة تشغيل المعاينة وتطبيق الهجرات متسلسلة بيد المنسق.

B6 لم يبدأ. لا نشر مستضاف أو تغيير DNS أو شراء أو APK في هذه المرحلة. إعداد الإنتاج وحدوده والبريد والنسخ الاحتياطي المستقل وقبول مستخدمين حقيقيين لها أدلة منفصلة في B7. بعد المراحل تُجرى المراجعة الشاملة التي طلبها المستخدم، ويكتب تقرير الرصد قبل بدء إصلاحاتها.
