# B0 — نتيجة التنفيذ والتحقق

31 أكتوبر 2026. **الأساس المحلي نُفّذ وتحقق؛ البيئة البعيدة وCPU المستضاف لم يُختبرا.** هذه حدود مرحلة الأساس، وليست حسابات B1 أو رحلة B2 مكتملة أو تطبيق Android.

## الناتج الفعلي

- مستودع pnpm واحد مع Next/Workers وعميل React مستقل وحزم عقود وعميل وواجهة مشتركة؛ lockfile وإصدارات مثبتة، TypeScript وLint واختبارات وإعداد CI محلي.
- حفظ 104 ملفات هوية/واجهة مرجعية دون تعديل المصدر، مع SHA-256 وحقوق الاستخدام. اللاندنج المقبولة محفوظة؛ صفحة B0 تقنية مستقلة وليست بديلًا عنها. [دليل الأصول](B0_ASSETS.md).
- PostgreSQL + GoTrue + PostgREST حقيقية محليًا؛ migration وRLS للمالك وحسابات صناعية؛ لا service-role في تطبيق الويب. [دليل الباك إند](B0_BACKEND.md).
- صفحة واجهة وAPI `/api/v1` تحفظ وتقرأ سجلًا تجريبيًا مصرحًا؛ نفس المكونات والعميل تعمل ببناء Vite منفصل، دون استيراد Next الخادمي في حزمة العميل.
- [عقد API والمصادقة](../B0_API_AND_AUTH_AR.md)، [حالات أول رحلة وwireframes](../B0_UX_STATES_AR.md)، و[دليل التشغيل](../RUN_LOCAL_AR.md).

## القرار التقني الذي أثبته الاختبار

| المكون | الإصدار/القرار المختبر |
|---|---|
| Node / pnpm | 22.23.4 / 10.15.0 |
| Next / React | 16.4.3 / 19.3.1 |
| Workers adapter / CLI | OpenNext Cloudflare 1.20.15 / Wrangler 4.156.0 |
| Workers compatibility date | 2026-10-23، متوافق مع workerd المحلي المثبت |
| Supabase JS | 2.118.0 |
| Types / contracts | TypeScript 5.9.3، Zod 4.6.7 |
| Standalone client | Vite 8.3.5 + نفس React/UI/client/contracts |
| قاعدة التطوير | subset محلي فعلي Auth/Postgres/REST؛ صور مثبتة بالـdigest |

توثيق Cloudflare الحالي يعرض vinext كمسار موصى به لكنه Beta؛ اخترنا واختبرنا OpenNext مع Next نفسه كمسار موثق آخر، دون تبني إعادة تنفيذ جديدة الآن. هذا قرار B0 قابل للمراجعة عند وجود دليل، لا افتراض أن المسار الرسمي القديم ما زال الوحيد. [Cloudflare Next.js](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)، [OpenNext](https://opennext.js.org/cloudflare/get-started).

واجه البناء خارج tracing root مشكلة فعلية مع external pnpm virtual store. حلّها build mirror داخل Data2 بمدخلات مطابقة واعتمادات داخل جذره؛ لا patch لمكتبات Next/OpenNext ولا تعطيل للفحوص. الجهاز العادي وCI يبنيان مباشرة من المستودع. الإعداد معزول في `.local/worker-build.json` ولا يُنقل إلى Git.

فحص الاعتمادات كشف advisories في glob/minimatch ضمن أدوات OpenNext. override محدد لاعتمادي glob لدى OpenNext وnode-minify إلى 14.0.2، ثم أُعيد البناء والتحقق. النسخة المقفلة في lockfile هي المرجع؛ تُراجع هذه overrides عند ترقية upstream.

## الأدلة المنفذة

| التحقق | النتيجة والحد |
|---|---|
| `pnpm check` | TypeScript وESLint ناجحان، 6 اختبارات في 3 ملفات ناجحة |
| `pnpm build` | build Next + OpenNext كامل، Worker مولّد؛ النسخة المعزولة تطابق بصمة المصدر |
| `pnpm build:client` | HTML/CSS/JS مستقل ناجح، نفس الواجهة والعقود والعميل؛ ليس APK |
| `pnpm test:backend` | 12 حالة على Auth/DB/REST الحقيقية: هوية، حفظ، RLS، تزوير المالك، مجهول، حدود مدخلات، preflight |
| `pnpm test:api` | 12 حالة عبر workerd المحلي: قراءة/كتابة، عزل، هوية، origin، JSON، body limit وعميل مستقل |
| `pnpm test:browser` | رحلة فعلية ناجحة: دخول، حفظ، reload وإعادة دخول ثم قراءة نفس السجل، حساب ثانٍ لا يرى السجل أو المسودة؛ تسجيل دخول من عميل Vite وقراءة نفس البيانات |
| مراجعة العرض | صور 1280 و375px مفتوحة ومراجعة؛ اختبار عدم overflow عند 320 أيضًا؛ reduced motion/keyboard smoke فقط وليس تدقيق وصول شامل |
| مراجعة مستقلة | عيوب origins ومسودة الحساب صححت؛ ثم عيوب stale mirror env وحذف ملف tracked صححت مع اختبارات؛ verdict في نطاق المراجعة: ship |
| فحص الاعتمادات | `pnpm audit --prod --json`: صفر advisories معروفة وقت الفحص؛ ليس تدقيق أمان شامل |
| CI | workflow محفوظ بمراجع actions مثبتة؛ لم يُشغّل بعيدًا ولم يُرفع مستودع |

## CPU والأداء: ما لا تثبته التجربة

نجح تشغيل Worker عبر workerd، وأُجريت طلبات متتابعة بعد الإحماء على صفحة SSR وhealth وقراءة مصرح بها. JSON القياس يذكر p50/p95 للزمن الكلي محليًا والعينة؛ ليست اختبارات حمل أو أرقام أجهزة المستخدمين.

local observability أعادت CPU وwall بصفر رغم وجود زمن فعلي للطلبات؛ لم نعتمدها كقياس CPU. **لا إثبات بعد أن طلبات التطبيق الحقيقي تلائم حصة Workers Free، ولا ضمان سعة 50–100 مستخدم.** يلزم قياس بيئة بعيدة مع Auth وقواعد المنتج والأحمال الفعلية قبل الإطلاق. هذا بند معلّق ظاهر، لا نتيجة ناجحة مختلقة.

## الحدود المتبقية

- لا إنشاء/تعديل Cloudflare أوSupabase مستضاف أوSpaceship، ولا DNS أونشر أوتكلفة جديدة.
- B1 لم يبدأ: Google OAuth وOTP/SMTP والجلسة المستمرة وملف المستخدم والأدوار الحقيقية ما زالت مراحل لاحقة. التسجيل الحالي email/password مؤقت وautoconfirm محلي فقط.
- بناء العميل يثبت فصل React عن خادم Next؛ لم يُبنَ APK ولم تُختبر إشعارات/خلفية/روابط Android. M0/M1 باقيان كما خُطط لهما.
- لا Realtime/Storage/Cron أو منطق تخطيط/إنجاز/وقت/رومز إنتاجي. مخطط probe لا يستبدل نموذج المنتج، ويُزال قبل B7.
- معايير المصدر/الرخص الموضحة في دليل الأصول باقية؛ لا ادعاء تطابق مصدر صورة مفقود أو حقوق حصرية لطرف ثالث.
- التحقق من إعادة إنشاء قاعدة نظيفة والاستعادة والحمل وتدقيق وصول شامل وCI الفعلي مؤجل لبواباته. تشغيل الخدمات المتكرر نجح دون حذف البيانات.

يمكن متابعة B1 اعتمادًا على الأساس المحلي؛ الإطلاق العام ما زال محكومًا بجميع بوابات B7.
