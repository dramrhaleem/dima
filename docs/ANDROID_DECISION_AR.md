# ديمة — قرار دعم Android

31 أكتوبر 2026 · إصدار 1.2 · طلب المستخدم تسجيل المسار الذي نوقش. هذه وثيقة تصميم واختبار مستقبلي، وليست إثباتًا لتوافق تطبيق مبني.

**تحديث B0:** نجح بناء وتشغيل واجهة React نفسها في Next/Workers وVite مستقل عبر نفس API محلي. هذا دليل فصل العميل فقط؛ لا APK أو اختبار جهاز Android، ولا تغيير لموقع M0/M1/M2. [دليل B0](evidence/B0.md).

## القرار وحدود الالتزام

نبني الويب أولًا مع قابلية إصدار Android باستخدام **Capacitor**. يبقى Cloudflare Workers للـAPI والويب، وSupabase للحسابات والبيانات وRealtime؛ لا باك إند ثانٍ ولا نسخ بيانات منفصلة للموبايل. الحساب والتقدم والسجل نفسهم عبر الأجهزة.

اختبار Android مصغّر **M0 بعد B2** يثبت الدخول والكورس والإنجاز المحفوظ. اختبار **M1 بعد B4** يثبت الوقت وسلوك الخلفية. إصدار Android الكامل **M2 بعد B7** مرحلة لاحقة؛ ليس شرطًا لإطلاق الويب، ولا وعدًا بموعد متجر أو بتطبيق native مكتوب من الصفر. الغرف تبقى P0 للويب كما في PRD.

Capacitor مسار إعادة استخدام واجهة ويب داخل حاوية Android مع إضافات للجهاز. لا نضع نسبة مئوية لإعادة الاستخدام قبل الاختبار. التطبيقات المكتوبة بـReact Native/Flutter مسار مختلف يستلزم إعادة بناء واجهات؛ ليست اختيارنا الحالي.

## حدود المشاركة والتنفيذ

| الجزء | العقد |
|---|---|
| بيانات المجال والصلاحيات والاحتساب | نفس الخدمة وقاعدة البيانات؛ الخادم المرجع للملكية والوقت والنقاط |
| HTTP API | `/api/v1` مستقل عن Server Actions؛ أوامر المجال تعمل من الويب وعميل Android |
| قواعد مشتركة | محرك التخطيط، الأنواع والتحقق في حزم TypeScript بلا اعتماد على Next أو DOM؛ حساب العميل للمعاينة لا يجيز الكتابة |
| التصميم | الشعار والتوكنز والمنطق التفاعلي مشتركة؛ تكييف التنقل واللمس والرجوع ولوحة المفاتيح للموبايل |
| الواجهة القابلة للتغليف | عميل React مبني إلى HTML/CSS/JS؛ لا نحاول تشغيل خادم Next داخل APK |
| المنصة | adapters للمصادقة والتخزين والإشعارات والروابط وlifecycle؛ لا نفترض أن cookies والمتصفح والـWebView يتصرفون بالطريقة نفسها |

الويب العام يمكن أن يستخدم إمكانات Next الخادمية. في B0 نختبر مسار بناء العميل المشترك: نعيد استخدام المكونات والمنطق، ونستخدم غلاف بناء خفيف للموبايل عند الحاجة بدل فرض static export على الموقع كله. لا نُثبت bundler أو adapter قبل إثبات توافقه. وجود Next في المشروع لا يضمن وحده قابلية تغليف جميع شاشاته.

## شروط يجب مراعاتها من أول تنفيذ

1. **المصادقة:** Google OAuth عبر مسار مدعوم خارج الـWebView عند الحاجة؛ PKCE وروابط عودة مسموحة ومحددة. اختبار تسجيل الدخول والإلغاء وانتهاء الجلسة وإعادة فتح التطبيق. منع open redirects وتسرب tokens للسجلات أو الروابط. لا service-role key في أي عميل.
2. **النقل والتخزين:** عقود الجلسة للويب والموبايل موثقة؛ cookies الويب لها حماية CSRF/Origin، وعميل الموبايل يستخدم آلية موثقة للتحقق وتجديد الجلسة والتخزين المناسب. السماح بأصول محددة دون اعتبار CORS بديلًا للصلاحيات. اختيار الإضافة وترخيصها وصيانتها في B0/M0.
3. **الوقت:** البداية والنهاية والحدود من الخادم. تعليق JavaScript أو إغلاق الشاشة لا يمدد الجولة ولا يبدأ التالية. عند العودة نجلب snapshot؛ وقت الجهاز وحده لا يحدد رصيد المنافسة.
4. **الإشعارات:** تنبيه النهاية مستقل عن رصيد الوقت. نختبر الإذن المرفوض/المسحوب، السكون، force-stop وإعادة التشغيل، وإلغاء التنبيه عند الإنهاء أو التصحيح. لا نَعِد بتنبيه دقيق في كل ظروف Android أو نطلب exact-alarm/foreground-service permissions قبل إثبات الحاجة والمسار المدعوم.
5. **الغرف في الخلفية:** تجميد الاتصال قد ينهي presence lease ويحرر المقعد وفق عقد الغرف؛ لا heartbeat وهمية ولا إعادة انضمام أو بدء جولة دون المستخدم. الوقت السابق المقبول محفوظ، والعودة تجلب الصلاحيات والحالة الحالية قبل عرض roster.
6. **Offline:** نفس حدود الويب: مسودات وأوامر مسموحة Pending sync؛ لا بدء جلسة مؤهلة أو تطبيق خطة دون اتصال. بيانات الحساب وطابوره معزولة وتُعالج عند الخروج والتبديل.
7. **تجربة الهاتف:** safe areas، زر الرجوع، لوحة المفاتيح، تكبير النص، reduced motion، فتح مصادر الكورسات خارجيًا، وروابط كورس/روم تعود لوجهتها بعد الدخول.
8. **الإصدارات:** build قابل لإعادة الإنتاج، إصدارات مثبتة، سياسة توافق للـAPI مع APK أقدم. M0 يستخدم APK تجربة؛ M2 يحتاج توقيعًا محفوظًا خارج Git، وسياسة تحديث وتوزيع. APK للتثبيت المباشر وAAB للنشر عبر Play بحسب المتطلبات وقتها؛ النشر وحساب المتجر غير منفذين ولا مأذونين بهذا التسجيل.

## بوابات القبول

| ID | الاختبار | النجاح المطلوب |
|---|---|---|
| AND01 | دخول وإلغاء OAuth ورابط كورس/روم ثم إغلاق وإعادة فتح | عودة صحيحة للوجهة، بلا جلسة مستخدم آخر أو token مكشوف |
| AND02 | إنجاز من APK ثم فتح الويب والعكس، مع retry لفقد الرد | نفس التقدم، عملية واحدة، ولا اعتماد على localStorage كحقيقة |
| AND03 | تبديل الحساب مع مسودة أو عملية Pending | لا بيانات أو إشعارات الحساب الأول للثاني |
| AND04 | جولة فردية ثم قفل الشاشة والسكون/قتل العملية | الحد الخادمي صحيح، لا رصيد استراحة أو بدء تلقائي؛ توثيق ما حدث للتنبيه |
| AND05 | إذن التنبيه مرفوض ثم مسحوب، وتعديل/إنهاء جلسة | حالة صادقة داخل التطبيق؛ لا تنبيه قديم مخطط بعد الإلغاء المحلي؛ معالجة وصول تحديث جهاز آخر حسب قيود الخلفية الموثقة |
| AND06 | انتقال التحكم بين الويب وAPK ومحاولة بدء متزامنة | جلسة واحدة، رفض التحكم القديم، لا وقت مزدوج |
| AND07 | روم في الخلفية حتى انتهاء lease ثم العودة | لا بيانات بلا صلاحية، Rejoin وفحص السعة، لا إهدار الوقت المقبول |
| AND08 | رجوع، لوحة مفاتيح، رابط خارجي، نص كبير وجهاز متوسط | رحلة قابلة للإتمام بلا حجب فعل أساسي أو تعطل تنقل |
| AND09 | تحديث APK/API مع طابور محلي قديم | مزامنة متوافقة أو ترقية مطلوبة برسالة تحفظ البيانات؛ لا replay مضاعف |

M0: AND01–AND03 وAND08 على رحلة B2؛ لا يغطي غرفًا لم تُبنَ. M1: AND04–AND06 للفردي بعد B4. M2: إعادة الحالات المتأثرة + AND07–AND09 والميزات الكاملة على هاتف فعلي، مع تسجيل إصدار Android والجهاز والطاقة والشبكة. المحاكي لا يثبت اعتمادية الخلفية على هاتف فعلي.

## إذا فشل الاختبار

نحافظ على عقود الباك إند، نحدد الجزء المقيد بإطار العمل ونجرب غلاف عميل مستقل مع المكونات القابلة للمشاركة. لا نعد بتغليف جاهز ولا نؤجل اكتشاف المشكلة إلى نهاية البناء. تغيير المسار إلى native كامل أو إضافة خدمة مدفوعة قرار نطاق منفصل موثق.
