# B2 — التعلم والخطة والتقدم

> هذه وثيقة أساس B2. [امتداد B3](B3_API_AND_RECOVERY_AR.md) يضيف العمل الجزئي والاستدراك، ويتقدم على حدود المرحلة المذكورة هنا.

## حدود التنفيذ

واجهات تعلم حقيقية على البنية المحلية المعتمدة. لا مزامنة مع حساب Coursera أو Harvard، ولا شهادات أو درجات أو ساعات مؤقت مستنتجة من الإكمال. الاستدراك المتقدم والجزئي والموقت والغرف والمنافسة مراحل لاحقة.

## عقد API

| المسار | الغرض |
|---|---|
| `GET /api/v1/catalog` | عرضان عامان بمناهجهما المراجعة |
| `GET /api/v1/catalog/:id` | نسخة العرض المنشورة الحالية |
| `GET /api/v1/learning` | حالة صاحب الحساب فقط، المنطقة الزمنية واليوم المحلي |
| `POST /api/v1/learning` | أمر مكتوب النوع مع `operationId` و`expectedRevision` |

الأوامر: `saveDraft`, `enroll`, `setEstimates`, `preview`, `apply`, `complete`, `undo`. تعريفاتها الملزمة في [learning.ts](../packages/contracts/src/learning.ts). طلبات cookies تحمل `X-Dima-Account-Id` وOrigin من التطبيق؛ عملاء Bearer يمرون بتحقق الهوية نفسه. كتالوج عام يدعم CORS للأصول المسموحة فقط.

حفظ المسودة لا ينشرها. الانضمام يثبت نسخة المنهج والنطاق والإنجاز السابق؛ تحرير المسودة لاحقًا لا يبدل نسخة المنضم. تقديرات المستخدم منفصلة عن المصدر. لا يجعل اختيار نطاق جزئي الكورس الكامل مكتملًا.

## الحفظ والصلاحيات

`learning_workspaces` تجميعة خاصة ذات revision تضم المسودات والاشتراكات المجمدة والخطة والأحداث الحالية. هذا يحافظ على تطبيق أمر واحد ذريًا في B2، دون محاولة نشر حالة المستخدم. `learning_operations` يحتفظ بالأمر وإيصال مختصر؛ لا يكرر المنهج الكامل مع كل إنجاز. الإسقاطات الاجتماعية والاستعلامات العامة في B6 مستقلة ولم تُنشأ.

الدخول يثبت عبر Auth أولًا، ثم يمر الأمر بالتحقق ونموذج المجال الخادمي. دالة الكتابة لا يستطيع `anon` أو `authenticated` استدعاءها مباشرة؛ يستدعيها خادم API بدور خادم خاص فقط. RLS يتيح قراءة المالك؛ لا تعديل مباشر عبر REST. نفس قفل الحساب مع B1 يمنع سباق تغيير المنطقة الزمنية وتطبيق خطة. SQL يتحقق من revisions مرة أخرى داخل transaction.

إعادة نفس الأمر لا تنفذه مرتين، وتعيد الحالة الحالية بدل إرجاع snapshot قديم يغطي تعديلًا أحدث. تغيير محتوى أمر مع نفس المعرف مرفوض. مفتاح دور الخادم محلي وسري، ولم يُضف إلى عميل الويب أو Vite.

## قواعد التخطيط

- سعة أسبوعية واحدة لكل كورسات المستخدم؛ 15% احتياطي يومي؛ صفر يوم راحة.
- ترتيب حتمي حسب الهدف وترتيب المصدر والهوية؛ الاعتماد الصريح يحكم جاهزية الإكمال. فتح المصدر ممكن دائمًا.
- كتل بحد أقصى 45 دقيقة؛ الكتلة جزء من النشاط وليست إكمالًا تلقائيًا له.
- لكل كورس أفق حتى 90 يومًا بعد هدفه. هدف فائت يبقى كما اختاره المستخدم؛ لا يزاح تلقائيًا. إن انتهى الأفق يبقى العمل غير موزع مع سبب.
- التقدير المؤقت أو المفقود يمنع وعد `Fits` المضلل. تبقى الأجزاء غير الموزعة مرئية، واعتماد الجزء الممكن يحتاج إقرارًا.
- معاينة ثم Apply صريح. تغير التقدم/النطاق/التقدير/الملف/اليوم المحلي أو انتهاء 24 ساعة يبطل المعاينة.
- Complete يتطلب تأكيد النشاط كله وتقدير الجهد أو إعلان عدم معرفته. الجهد يستهلك السعة التخطيطية فقط؛ ليس وقت تايمر. الجهد المجهول يغلق سعة اليوم المتبقية أمام التوزيع التلقائي.
- السابق في الإجمالي فقط؛ لا استحقاق جديد أو وقت. Undo/Recomplete يحافظان على هوية أول إكمال، دون خلق نقاط متكررة. Undo تصحيح لعلامة خاطئة؛ العمل الجزئي المستقل يأتي في B3.

## البوابات

اختبارات المجال تتحقق من السعة والترتيب والحالات الحدية. اختبار API المحلي يختبر الحفظ وRLS والتزامن والإعادة. رحلات المتصفح تختبر الإدخال والحفظ الفاشل والجهاز الثاني والموبايل. النتائج الفعلية وحدودها في [تقرير B2](evidence/B2.md)؛ هذه الوثيقة لا تثبت نجاح التشغيل وحدها.
