# ديمة — التخطيط والاستدراك والتقدم والمشاركة

عقد تنفيذ D03–D06 و D09–D12. إصدار 1.0، 31 أكتوبر 2026. الأرقام الموسومة «افتراضي تجريبي» قابلة للتعديل بإصدار قواعد؛ لا تتغير داخل خطة مقبولة بصمت.

## 1. مفاهيم لا تُدمج

| الكيان | معناه | ما لا يعنيه |
|---|---|---|
| Curriculum | Program اختياري ← Course ← Module ← Task بهويات مستقرة | ليس خطة كل مستخدم |
| Offering / Version | نطاق منشور ونسخة منهج للمقارنة والانضمام | ليس نسخة قابلة للتعديل الحي من صاحب الكورس |
| Enrollment | اختيار المستخدم للنطاق والنسخة وتقدمه السابق | لا ينشر اسمه تلقائيًا في People |
| Plan / Block | توزيع العمل على أيام مع سعة وتقديرات | إتمام block لا يكمل task تلقائيًا |
| WorkEvent | عمل جزئي قبله المستخدم على block مع تقدير المتبقي | دقائق التايمر ليست بديلًا تلقائيًا لهذا التقدير |
| CompletionClaim | أول إكمال مؤهل لهوية نشاط ثابتة | لا يتكرر مع Undo/Recomplete أو تحديث المنهج |
| Time interval | فترة وقت ذات مصدر وحدود وأهلية | ليست إثبات فهم أو إنجاز درس |

الأنشطة Required / Optional / Supporting / Alternative. الفيديو والنص البديل لنفس المحتوى لا يحتسبان متطلبين مستقلين. لا يُدّعى اكتمال الكورس كله إذا اختار المستخدم جزءًا منه؛ يظهر «Your selected scope» منفصلًا عن «Full course».

## 2. إنشاء المنهج والخطة

1. اختيار مكتبة أو Private course. الخاص usable فورًا؛ نشره مسار مستقل.
2. اختيار النطاق؛ فهرس المصدر محفوظ بترتيبه، مع URL ونوع النشاط وتقديره ومصدر التقدير.
3. تحديد الإنجاز السابق اختياريًا مع معاينة؛ يحتسب في الإجمالي ولا يمنح نقاط هذا الأسبوع.
4. تأكيد تاريخ البداية والهدف، IANA timezone، أيام التوفر والراحة، الأولويات. لا نستخدم تاريخ إعداد الوثيقة كتاريخ بداية فعلي.
5. سعة واحدة لكل المستخدم عبر جميع كورسات التعلم. Work sessions لا تغيرها؛ إذا غيّر العمل المتاح يُحدّث المستخدم availability.
6. معاينة يمكن قبولها أو تعديلها. لا يصح بدء الخطة بصمت عند إضافة كورس ثانٍ.

يمكن عرض Light / Standard / Full = 60 / 120 / 180 دقيقة تقديرية ليوم دراسة كافتراض تجريبي. المعاينة تشرحها بأمثلة أنشطة؛ المستخدم يرى «ماذا ينجز» لا التزامًا بتشغيل مؤقّت كل هذه المدة.

ترتيب تقدير المتبقي: تقدير المستخدم الصريح ← تقدير مصدر تمت مراجعته ← فئة جهد يختارها المستخدم Small/Medium/Large = 10/30/60 ← fallback معلن. إن لم يوجد غير مدة الفيديو، يمكن اقتراح ×1.25، مع وسم أنه افتراض. لا نضرب تقدير جهد منشور مرة أخرى. Fallback: فيديو 15، قراءة 15، اختبار 20، assignment60؛ project/وحدة غير مفصلة تحتاج تقديرًا أو تقسيمًا، لا دقة وهمية.

حالة التقدير Source-based / User-estimated / Provisional / Missing. يظهر مقدار العمل ذي التقدير المؤقت/المفقود. اقتراح تعديل تقديرات مستقبلية بعد Lighter/Heavier لا يعدّل الخطة أو النقاط تلقائيًا.

## 3. خوارزمية التوزيع وقواعد السعة

هذه heuristic حتمية قابلة للاختبار وليست برهان optimal scheduling.

1. التقط revisions للخطة والتقدم والنطاق والنسخة والسعة و WorkEvents والتقديرات.
2. افحص التقديرات والمتطلبات السابقة والدورات. Missing ينتج خطة Provisional، وليس Fits.
3. ثبّت التاريخ المكتمل والعمل الجزئي والراحة والاستثناءات والكتل المثبتة. استدراك الماضي يبدأ من المتبقي اليوم والمستقبل فقط.
4. احتفظ بـ 15% من السعة اليومية كاحتياطي استدراك تجريبي. الراحة سعتها صفر، واستثناء اليوم يتقدم على الأسبوع المعتاد.
5. المتبقي المؤكد للنشاط يشمل مثبتاته غير المنجزة: Remaining100 و Pinned45 يعني Flexible55. اخصم المثبت مرة من المتبقي ومرة من سعة يومه، كل منهما لغرض مختلف؛ لا تخصمه مرتين من أي وعاء.
6. سعة مرنة اليوم = Ceiling − Reserve − Accepted work effort today − Incomplete pins today. الكتل المرنة التي سيستبدلها preview لا تُخصم قبل إعادة توزيعها.
7. مثال: Ceiling180، Reserve27، عمل مقبول 40، Pins45 → مساحة مرنة 68. إذا تجاوزت المثبتات المتبقي أو السعة، اعرض تعارضًا ولا تصلحه بالقص الصامت.
8. صف العمل الجاهز حسب أقرب target، ثم أولوية المستخدم، ثم ترتيب المصدر، ثم stable ID. المتطلبات الصريحة تحكم الاعتماد؛ الترتيب الموصى به ليس منعًا اصطناعيًا من فتح المحتوى.
9. وزّع أول block جاهز في أول يوم مسموح يتسع له. اقتراح حد block45 دقيقة؛ استخدم فواصل محتوى طبيعية إن وجدت، وإلا سمِّه Continue assignment — block 2.
10. إتمام block مخطط ليس إتمام المتطلب السابق فعليًا. Today يبيّن الاعتماد غير المنجز ويتيح المستخدم فهم السبب.
11. احتساب forecast يبحث حتى 90 يومًا بعد الهدف. إن لم يجد توزيعًا، يظهر عدم العثور ضمن الأفق؛ لا يُخترع تاريخ نهاية.
12. الناتج يحمل كل العمل: Scheduled + Unscheduled + Paused/excluded. لا تسقط متطلبات للوصول إلى لون أخضر.

الحالات: **Fits estimated workload** إذا كل العمل المعلوم يطابق القيود؛ **Provisional** عند نقص المعرفة؛ **Capacity conflict** عند تجاوز حسابي مثبت للسعة؛ **No schedule found under these rules** عند فشل heuristic دون إثبات استحالة.

**اعتماد خطة جزئية:** يمكن اختيار Apply feasible part إذا وُجد توزيع صالح لبعض العمل، مع إقرار واضح بعدد/حجم العمل غير الموزع وسبب بقائه؛ تبقى حالة الخطة Provisional/Needs attention ولا توصف بأنها تحقق الموعد. يظهر backlog دائمًا في Today/Plan إلى أن يُحل. لا يُسمح بتجاوز السعة أو الاحتفاظ بمثبتات متناقضة؛ يجب إصلاح هذا التعارض أولًا. مهام dependencies غير المحسومة تبقى غير موزعة، ويمكن توزيع المسارات المستقلة الصحيحة. إذا لم يوجد أي عمل قابل للتوزيع، تُحفظ مسودة فقط ويظل Focus اليدوي متاحًا.

## 4. الاستدراك بعد الغياب

المحفّز: انتهى يوم دراسة محلي وله عمل غير منجز يحتاج إعادة توزيع. الراحة و Pause والأيام بلا مهام ليست تعثرًا. لا نستنتج سبب الغياب أو نقول إن المستخدم كسول.

| الحالة | Today | Recovery |
|---|---|---|
| يوم واحد | بطاقة هادئة واحدة؛ النشاط التالي لا يختفي | توزيع المتبقي داخل السعة، واستخدام الاحتياطي خيار ظاهر |
| يومان | «Your progress is saved» وعدد الأنشطة المحتاجة لموعد | يحافظ الافتراضي على الحمل؛ يكشف forecast الجديد إذا لزم |
| تكرار التعثر في 3 أيام دراسة خلال 14 يومًا | اقتراح اختياري لمراجعة الحمل؛ عتبة تجريبية | أيام أقل/سعة أخف/تغيير أولوية/Pause كورس، دون فرض |
| انقطاع طويل | آخر موضع محفوظ + Start small + Review plan | تحديث التوفر والتقدير قبل توقعات جديدة |
| لا وقت حتى الموعد | لا وعد «هتلحق» | الهدف ثابت، العجز والتوقع واضحان؛ بدائل للمستخدم |

«Start small» يختار أول نشاط جاهز من الكورس ذي الأولوية. إذا حجمه أكبر من 15 دقيقة يقترح block15 من نفس النشاط؛ ليس نشاطًا وهميًا ولا يمنح إكمالًا كاملًا. التسجيل يحدّث work history، ويجعل أي preview قديم stale. بعده يمكن الاستدراك؛ لا يُجبر المستخدم على معالج كامل قبل العمل.

خيارات المعاينة: **Keep my workload** الافتراضي؛ **Use recovery buffer** داخل السقف؛ **Adjust availability** مع أثر صريح؛ **Change target / priority / Pause course**. لا يغير اختيار «حافظ على الموعد» السقف أو أيام الراحة تلقائيًا. إذا فشل التوزيع يبقى الفشل مرئيًا.

المعاينة تعرض before/after، الأنشطة المنقولة، الحمل اليومي، استخدام الاحتياطي، target مقابل forecast، المتبقي غير الموزع، وسبب كل تغيير مهم. قبولها transaction يتحقق من revisions؛ stale → تحديث ومعاينة جديدة. بعد 24 ساعة تُعاد المعاينة حتى لو لم تتغير revisions، كقاعدة تجريبية.

Undo للاستدراك يُنشئ اقتراح توزيع جديدًا وفق التقدم الحالي؛ لا يعيد snapshot تقدم قديمًا. «Later today» يغير ترتيب الاقتراح داخل اليوم فقط؛ «Move to another day» يفتح معاينة؛ «Take a rest day» يعدل availability بمعاينة، ولا يصنع إنجازًا.

### مثال حسابي يمكن اختباره

متبقٍ يحتاج إعادة توزيع 150 دقيقة؛ يومان مقبلان، سعة كل يوم 60 واحتياطي 9. المساحة الافتراضية 102، والعجز 48. استخدام الاحتياطي يجعل المساحة 120 والعجز 30؛ فلا يكفي الحفاظ على الموعد حتى بعد الاحتياطي. يعرض النظام يومًا إضافيًا بالتوقع أو تعديلات يختارها المستخدم، ولا يكدّس 150 في يوم 60.

## 5. الإنجاز الجزئي والخارج عن الخطة

- Worked on يحفظ WorkEvent وكمية الجهد التخطيطي المقبولة؛ يقترح المتبقي ويسأل عن تأكيده.
- نشاط 120 وعمل 40 → يقترح 80؛ دون تأكيد يبقى Remaining unknown، لا 120 جديدة ولا 0 وهمية.
- استخدام آخر block دون إكمال النشاط يظهر More work needed؛ تبقى المهمة غير مكتملة حتى التصريح بذلك.
- Complete مباشرة دون Worked on لا يستهلك يومًا «مجانيًا»: قبل الفعل تعرض الواجهة الجهد التخطيطي المتبقي المقترح، ويستطيع المستخدم تعديله. الإقرار يولد WorkEvent بذلك الجهد في يوم الإنجاز المحلي، لا ساعات Timer. المتبقي المؤكد يشمل كل العمل غير المنجز فقط، فلا يُخصم عمل سابق مرة ثانية. مثال: أصل 120، Worked40، متبقٍ مؤكد 80؛ Complete يقبل 80 جديدة، فيكون المستهلك 120 إجمالًا لا 160. Baseline لا يستهلك سعة اليوم.
- إذا أكد الإكمال ولا يعرف الجهد، يُحفظ الإنجاز ويصبح استهلاك يومه Unknown؛ لا يملأ المحرك بقية هذا اليوم تلقائيًا قبل تأكيد الجهد أوالسعة المتبقية. يمكنه توزيع الأيام التالية والبدء يدويًا. مصدر WorkEvent الناتج completion ومرجع الحدث فريدان لمنع التكرار.
- الإكمال خارج الخطة يُقبل ويزيل العمل المستقبلي المطابق عبر مراجعة الخطة؛ لا يعيد إنجازًا إلى المتأخرات.
- Undo completion يصحح التقدم، ويُبطل المعاينات التابعة، ويسحب استحقاق نفس claim حتى يعاد إكماله؛ لا يصنع first claim جديدًا.
- Undo لعلامة أُدخلت بالخطأ يبطل فقط WorkEvent المولّد من ذلك الإكمال. Worked on مستقل أوإنجاز لاحق لا يُمسح؛ المتبقي يُراجع وفق الأحداث الحالية. خيار Reopen مع Keep recorded work متاح إذا كان العمل حدث فعلًا وما زال يحتاج تكملة. التصحيح لا يُطبّق خطة جديدة بصمت.
- Archive enrollment يوقف المستقبل ويحفظ التاريخ. Pause له تاريخ بدء/استئناف واضح؛ لا يحذف المتطلبات.
- تغيير timezone يحتفظ بطوابع UTC وسياق اليوم الأصلي؛ إعادة تعيين أيام الخطة المحلية تحتاج معاينة. لا يتكرر استحقاق بسبب تغيير المنطقة.

## 6. تقدم النفس: أربع لوحات لا رقم واحد

| المؤشر | الحساب/المعنى | العرض |
|---|---|---|
| Course progress | وزن Required المكتمل ÷ وزن Required في النطاق المختار | السابق على التسجيل + الجديد؛ نسبة وخطوات فعلية؛ ليس إتقانًا |
| Time | مجموع فترات شخصية غير متداخلة؛ Timer و Manual منفصلان | Learning/Work؛ يوم/أسبوع/شهر؛ break منفصل خارج التركيز |
| Weekly rhythm | أيام نشاط ذات معنى ÷ هدف أيام الأسبوع | راحة/نشاط/بلا نشاط رموز مختلفة؛ لا streak إلزامي |
| Plan health | هدف مقابل توقع وفق المتبقي والسعة الحالية | آخر تحديث، نسبة تقديرات مؤقتة، وحاجة مراجعة |

يوم تعلم ذو معنى: أول إكمال فعلي جديد غير baseline، أو≥10 دقائق تعلم شخصية مسجلة، بما فيها إدخال يدوي معلن المصدر. يوم عمل:≥10 دقائق عمل شخصية. لا يكفي تسجيل الدخول/دخول الروم/تعديل الخطة. هذا تعريف قياس تجريبي وليس حدًا لقيمة التعلم؛ جلسة 5 دقائق تظهر في السجل حتى لو لم تحقق مؤشر اليوم.

هدف الإيقاع يُقترح من أيام الدراسة؛ لمستخدم العمل فقط يُقترح 3 أيام ويمكن تخطيه. تغيير الهدف يسري من الأسبوع القادم افتراضيًا؛ إن اختار الحالي يُعرض goal revised، ولا يعاد تلوين أسابيع سابقة. الاحتفال بعودة حقيقية اختياري وقصير ولا يمنح نقاطًا. يمكن تعطيل التحفيز والترتيب تمامًا.

مقارنة هذا الأسبوع بالسابق تستخدم نفس الجزء المنقضي أو أسبوعين كاملين. موعد الحد المحلي يختلف عن أسبوع المنافسة UTC؛ يُكتب ذلك في التفاصيل. التتبع يدوي/خادمي حسب المصدر، دون ادعاء verified learning.

## 7. لوحات الترتيب

| اللوحة | المقياس | القيود |
|---|---|---|
| Global hours | ثوانٍ مؤهلة نهائية؛ All / Learning / Work | أسبوع وشهر UTC؛ مشاركون opt-in فقط؛ ليست ترتيب جودة |
| Course — This week | مجموع أوزان first completions الجديدة في الأسبوع | نفس offering/version/comparison scope؛ لا baseline |
| Course — Overall | وزن Required المكتمل ÷ إجمالي Required | السابق يدخل في الإجمالي؛ صفر مقام يعني لا ترتيب |

أوزان سياسة v1: Video/Reading=1، Quiz=2، Assignment=4، Project=8. الدرجات معيار نشاط تقريبي وليست تقييم صعوبة علمي. Optional/Supporting خارج المقام والترتيب الأساسي. لا تغير تقديرات جهد شخص نسبة نقاطه. المراجعة تنشر scope ونسخة scoring ثابتين.

ComparisonScope يُنشئه المراجع لنطاق عام معلن مثل كورس كامل أو برنامج كامل؛ اختيار المستخدم subset لا ينشئ leaderboard جديدًا. يمكنه المنافسة في نطاق عام متوافق بعد معاينة المقام الكامل الذي سيستخدم، حتى لو كانت خطته الشخصية أصغر؛ تُعرض نسبته الشخصية منفصلة ولا تدخل بدل نسبة النطاق العام. اختلاف نسخة غير موثقة المطابقة لا يدمج المقارنات.

الأسبوع يبدأ الاثنين 00:00 UTC، والشهر تقويمي UTC؛ تظهر نهاية الفترة بالتوقيت المحلي. التعادل 1، 2، 2، 4؛ ترتيب عرض المتعادلين ثابت ولا يوحي بكسر التعادل. تعرض snapshot وقت الحساب و Pending عند التأخر. لا يتحرك صف أثناء نقر المستخدم؛ التحديث بعد Refresh أو حالة مستقرة.

Timer eligible = حدود قبلها الخادم أو نهاية مجدولة مسبقًا، دون تداخل أو تصحيح يدوي للفترة. الجلسات قيد التشغيل/المراجعة خارج اللوحة. اليدوي شخصي فقط؛ تصحيح فترة يسحب أهلية هذه الفترة وحدها ويحفظ مصدرها. لا نمسح دقائق صحيحة سابقة من جلسة متعددة الفترات. النوم/وجود المؤشر/الكاميرا ليس دليل تركيز.

أول claim لكل lineage ثابت. Undo/Recomplete يستعيد نفس استحقاق الأسبوع الأصلي؛ لا يمنح أسبوعًا جديدًا. ما أُدخل كـ baseline يبقى baseline. اكتمال offline يحتسب تنافسيًا عند قبول الخادم، ويعرض Credited on مع التاريخ الشخصي إن اختلف. لا يُسمح بتغيير ساعة الجهاز لتزوير أسبوع المنافسة.

الانضمام المتأخر للوحة يعرض preview بالفترات والإجماليات التي ستصبح علنية؛ الانسحاب يسحب الصفوف ولا يمحو السجل. الاستخدام الكامل للخطة والتركيز متاح دون المنافسة. الطعون تستخدم Report ومراجعة مُسجلة؛ لا يتهم النظام المستخدم بالغش لمجرد ساعات مرتفعة.

## 8. دائرة المتابعة والخصوصية

المتابعة اتجاه واحد يحتاج قبول صاحب التقدم: None → Requested → Accepted، أو Declined/Cancelled/Removed. لا تصبح متبادلة تلقائيًا. الطلبات من ملف ظاهر أو People أو أعضاء روم مع إظهار الجمهور؛ يمكن تعطيل استقبالها. Block يلغي العلاقة والطلبات والتفاعلات بين الحسابين.

| السطح | الافتراضي | المشاركة الممكنة | ما لا يكشف |
|---|---|---|---|
| Profile | ملف خاص/غير قابل للاكتشاف العام | اسم عرض/avatar و bio قصيرة اختيارية | البريد والهوية الحقيقية الإلزامية أو آخر ظهور |

إذن المتابعة وحده لا يفتح كل المقاييس؛ عند قبول أول طلب تظهر معاينة «What they can see». Public profile اختياري ويستخدم alias قابلًا للتغيير بهوية داخلية ثابتة. ظهور اسم في روم/لوحة لا يجعل الملف كله عامًا.

Circle ليس feed لا نهائيًا: قائمة أشخاص، ملخص الأسبوع، آخر milestone اختيرت مشاركتها، رابط الكورس العام، و Nice work اختياري. لا تنبيه عن انقطاع شخص أو تجاوزه في الترتيب. عتبة تجريبية للتفاعل 20 تشجيعًا/يوم، وتفاعل واحد للشخص على نفس milestone؛ لا نقاط للتفاعل أو المتابعة.

المعلم الاجتماعي في v1 يقتصر على إنجاز في كورس عام اختار صاحبه نشره للمقبولين. له SharedMilestone مستقل ومنحة PublishedCourseMilestone ومعاينة للمحتوى؛ لا يُستنتج الإذن من مشاركة الساعات ولا تُشارك معالم العودة الخاصة تلقائيًا. Revoke أو Undo لمصدره يخفيه ويمنع تفاعلات جديدة. عدد الجلسات ليس حقلًا اجتماعيًا في v1. الملف العام على الإنترنت يظل الاسم/avatar/bio فقط؛ اللوحات لها إسقاط منفصل.

سحب الإذن/الحظر يتحقق في API والبث والكاش، لا في CSS. لا يمكن وعد المستخدم بمحو ما شاهده/صوّره غيره. البيانات التي اختار نشرها للإنترنت تظل قابلة للمشاهدة دون تسجيل، حتى لو حظر حسابًا؛ تُشرح هذه الحدود قبل النشر.

الإشعارات: داخل التطبيق للطلبات والنتائج وتحديثات المنهج؛ نهاية الجلسة مرئية وصوتها باختيار المستخدم. reminders الخارجية off افتراضيًا؛ لا prompt متصفح عند أول فتح. بعد تفعيلها: حد أقصى تذكير تخطيط واحد/يوم، هدوء 22:00–08:00 محليًا قابل للتعديل، ودون رسائل أثناء التركيز. لا يلزم إرسال push/email تحفيزي لإطلاق النسخة.

## 9. نشر منهج وترقيته

طلب النشر snapshot غير قابل للتغيير بعد الإرسال: عنوان/provider/رابط رسمي/لغة/بنية/أنواع/required flags/تقديرات ومصادرها/حقوق الوصف. لا يحتوي ملاحظات أو تقدم صاحب الطلب. Review: Pending → Changes requested → Resubmitted → Approved أو Rejected؛ سبب واضح ونسخ قرارات محفوظة.

المراجع يتحقق من التكرار والمصدر وحقوق الاستخدام والترتيب والأنشطة البديلة والتقديرات و lineage. لا تُنسخ دروس مدفوعة. عنوان مشابه يقترح ربط الموجود بدل نسخة جديدة؛ لا دمج تلقائي لنسختين مختلفتين.

ترقية المنهج تعرض added/removed/mapped/changed، تغير المقام والتوقع، والأنشطة ذات mapping غير محسوم. لا تُفرض الترقية. الهوية المقارنة ثابتة للنشاط المكافئ؛ mapping غير موثوق لا يمنح credit مكررًا. قبول النشر لا يُعيد تسجيل المساهم أو يضاعف تقدمَه السابق.
