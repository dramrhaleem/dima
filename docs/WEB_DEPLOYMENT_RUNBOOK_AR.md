# إطلاق ديمة — المسار العملي المختصر

الهدف: تشغيل الويب على dima.study عبر Cloudflare Workers + Supabase، دون تطبيق هاتف أو اشتراك مدفوع جديد. هذا دليل تنفيذ؛ نجاح أمر النشر وحده لا يثبت سلامة كل الرحلات.

## البيئة المعتمدة

- Worker: `dima-web`، والدومين `dima.study`، وحساب Cloudflare `2d027cf73931dd1e69aedaddcf801700`.
- مشروع Supabase: `vblsmzgbodqnlxlplnby`؛ بياناته مستقلة عن قاعدة التطوير المحلية.
- دخول Cloudflare متاح عبر Wrangler OAuth. جلسات Chrome الخارجية أتاحت إعداد الحسابات؛ وصف العائق القديم بأنه عدم تسجيل الدخول لم يعد ساريًا.
- إعداد البناء المحلي في `.local/worker-build.json` يحدد مرآة البناء. لا تدخل بيانات الاختبار أو ملفات `.dev.vars` في إعداد الإنتاج.
- الحالة الفعلية والحدود المتبقية تُقرأ من `docs/STATUS_AR.md` و`docs/evidence/B7.md`؛ لا تستنتج من وجود هذا الدليل.

## نشر تعديل لاحق

من جذر المشروع، نفّذ بالترتيب:

```sh
pnpm build
node scripts/production-deploy.mjs
node scripts/production-deploy.mjs --deploy
```

الأمر الثاني فحص جاف افتراضيًا؛ `--deploy` وحده يرفع الإصدار فعليًا. السكربت يرفض بناءً لا تطابق بصمته المصدر الحالي أو لا يحمل سجل ملكية المشروع. يستخدم نفس حصر الملفات وبصمة SHA-256 في `scripts/worker.mjs`، ولا يعيد البناء تلقائيًا.

ينشئ إعدادًا بلا أسرار داخل `.local/production-deploy/`: نفس الحساب وWorker والدومين، مع تعطيل `workers.dev` وروابط المعاينة، وضبط الأصل إلى HTTPS وتعطيل B0 وإبقاء Google مفعّلًا. لا يغيّر إعداد التطوير، ولا يقرأ ملفات أسرار الإنتاج، ولا يرفعها. أسرار Worker الحالية تُستخدم كما هي؛ `--keep-vars` يحتفظ بالمتغيرات البعيدة غير المعرفة في إعداد النشر. أي تغيير مقصود للأسرار عملية مستقلة لا تنفذها إعادة النشر المعتادة.

بعد نجاح الرفع، سجّل معرف إصدار Cloudflare وافحص رحلة HTTPS قصيرة مرتبطة بالتغيير: دخول، إعادة فتح بيانات محفوظة، وأي جلسة أو غرفة متأثرة. سجل `.local/production-deploy/last-deploy.json` يثبت نجاح أمرCLI وبصمة المصدر فقط؛ ليس شهادة تشغيل حي. CI الحالي هو الأنواع وLint والاختبارات السريعة والبناء، مع عدم تكرار الاختبارات الشاملة دون سبب جديد.

## قاعدة البيانات والمهام المجدولة

الهجرات محفوظة بالترتيب مع بصمات وسجل مستقل. لا تنقل قاعدة التطوير أو مستخدمي الاختبار ولا تعيد ضبط مشروع قائم. الهجرة040 تتضمن بذرتي المكتبة العامتين. مسار الإنتاج يسجل تخطي فحصB0 التطويري، ويستخدم محول Realtime مستضافًا دون تعديل الهجرات الأصلية. التفاصيل في `docs/evidence/HOSTED_MIGRATION_PREFLIGHT.md`.

```sh
node scripts/production-migrate.mjs --config /home/amro/.local/state/dima-production/connection.json
node scripts/production-migrate.mjs --config /home/amro/.local/state/dima-production/connection.json --apply
```

الأول قراءة فقط، والثاني تطبيق الهجرات الناقصة مع التحقق من السجل. تغيير ملف سبق تطبيقه مرفوض؛ الإصلاح بهجرة جديدة أو محول موثق عند اختلاف المنصة.

الـdispatcher يعمل كل دقيقة عبر Supabase Cron/HTTP إلى `/api/internal/jobs/dispatch`، والتوكن في Vault. للتحقق دون تعديل:

```sh
node scripts/production-cron.mjs --config /home/amro/.local/state/dima-production/connection.json --verify
```

تبقى `net` و`vault` و`dima_deploy` خارج Data API. يضع `pg_net` ترويسة التصريح مؤقتًا في طابور تديره المنصة؛ مشغّل قاعدة البيانات المباشر يستطيع قراءتها. لا تُضف API لتنفيذSQL حر أو تكشف هذه المخططات. سجلات التنفيذ المنقحة في `B7_HOSTED_CRON.json`.

## متغيرات وأسرار الإنتاج

إعداد الخادم يحتاج `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` و`DIMA_REALTIME_SIGNING_SECRET` و`DIMA_JOBS_TOKEN`. مفتاح الخدمة وسر توقيعRealtime وتوكن المهام أسرار خادمية فقط. لا تستخدم قيم localhost أو قيم التطوير في الإنتاج. تغيير سر المهام يتطلب تنسيق قيمةWorker معVault؛ وتغيير مفتاحRealtime يتطلب مفتاحًا يقبله المشروع المستضاف، لا مجرد نص عشوائي جديد.

إعداد Auth يستخدم `https://dima.study` ومسار `/auth/callback`. لا تعلن توفر البريد أو Google دون تجربة الوسيلة نفسها على البيئة المستضافة. التواصل العام المعتمد هو `support@dima.study`؛ توثيق إعداد العنوان منفصل عن إثبات تسليم الرسائل. تعيين مسؤول يتم من الخادم لحساب ثبتت هويته، وليس من بيانات البروفايل.

## الرجوع عند عطل الإطلاق

احتفظ بمعرف إصدارWorker السابق والجديد. يمكن إعادة الكود السابق إذا ظل متوافقًا مع المخطط؛ لا تسقط جداول أو تستعد قاعدة قديمة كحل سريع. استعادة البيانات تحتاج مراجعة الحسابات المحذوفة وأذونات المشاركة منذ النسخة. لا تصف الرجوع بأنه مجرّب إنتاجيًا ما لم يُنفذ فعلًا.
