# ديمة — عقد التركيز الفردي والرومز الجماعية

**الإصدار:** مواصفات قبل البناء، 31 أكتوبر 2026. طلب المستخدم يجعل البومودورو الفردي والجماعي والرومز العامة المرتبطة بموضوع أو كورس جزءًا أساسيًا من v1. الأرقام أدناه قرارات تصميم ابتدائية مفوّضة، لا نتائج اختبار أو حدود مثبتة للبنية الحالية.

## 1. تجربة واحدة بثلاثة أنماط

| النمط | الساعة | ماذا يُحفظ؟ |
|---|---|---|
| Open focus | عداد شخصي مفتوح، بسقف الفترة المعتمد | Session وفترات فعلية مقبولة؛ يمكن Work أو Learning |
| Solo Pomodoro | تركيز واستراحة محددان للمستخدم | وقت التركيز وحده؛ كل جولة تحتاج بدءًا صريحًا |
| Room Pomodoro | مراحل مشتركة يراها أعضاء الروم | ساعة الروم مستقلة عن وقت كل شخص؛ الانضمام للجولة إجراء صريح |

إنهاء التركيز لا يكمل مهمة، وإكمال المهمة لا يولّد وقتًا. يمكن ربط Learning بمهمة خاصة، أو التعلم دون خطة؛ نوع Work لا يتطلب كورسًا. اختيار الموضوع أو الروم ليس دليلًا على الدراسة أو الإتقان.

**المكوّن المشترك:** مؤقّت واحد عبر Today، المهمة، Focus، والروم. لا ننشئ عدادًا آخر لكل صفحة. وجود جلسة Running أو Paused أو Needs review يمنع بدء جلسة فردية أو جماعية أخرى حتى حسمها.

## 2. الإعدادات وقواعد البومودورو

| الإعداد | القيمة الابتدائية |
|---|---|
| Preset الأساسي | 25 دقيقة تركيز / 5 قصيرة / 15 طويلة بعد 4 جولات |
| Preset بديل | 50 دقيقة تركيز / 10 قصيرة / 20 طويلة بعد 4 جولات |
| تخصيص الفردي | تركيز 5–90 دقيقة، قصيرة 1–30، طويلة 5–60، بعد 2–6 جولات؛ أعداد صحيحة |
| تخصيص الجماعي | اختيار أحد الـ Presets قبل Start؛ 4 جولات لكل Run؛ لا تعديل أثناء Run |
| بدء جولة شخصية تالية | يدوي؛ الاستراحة يمكن أن يبدأ عرضها تلقائيًا، لكنها لا تمنح وقتًا |
| الصوت | غير مفعل تلقائيًا؛ اختيار شخصي، مع بديل بصري وعدم افتراض سماعه في الخلفية |
| سقف الروم | 20 عضوًا حاضرًا، يشمل المضيف، في التجربة الأولى |

هذه Presets للتركيز وليست ادعاء أن مدة واحدة تناسب كل الناس. خيار Open focus يظل متاحًا لمن لا يناسبه التقسيم. سقف الفترة المتصلة المقترح سابقًا، 4 ساعات، يظل حماية عليا؛ نهاية الجولة المحددة أقصر منه فتغلق وقتها أولًا.

**تخصيص صريح للعقد القديم:** نهاية الجولة المخططة مسبقًا تنتج Finalized، أما سقف الحماية للعداد المفتوح فينتج Needs review. القاعدة القديمة «بلوغ السقف يحتاج مراجعة» لا تُطبّق على كل جولة بومودورو. تصحيح Offline Stop المبكر يظل استثناءً مؤثرًا في الأهلية حتى بعد الإنهاء الآلي.

الفردي: Ready → Focusing → Break → Ready. Pause يوقف الوقت الشخصي ويحتفظ بالمتبقي؛ Resume متصل بالخادم يحسب نهاية جديدة من المتبقي فقط. Finish early يحفظ العمل الفعلي ويعرض استراحة اختيارية. التخطي إلى الاستراحة لا يمنح وقت الجزء المتروك. تعديل المدد يسري على الجولة التالية؛ لا يعيد تفسير الجولة المسجلة.

## 3. الروم والـ Run والجولة ثلاثة أشياء

- **Room:** عنوان عام وموضوع وقواعد وضبط ظهور؛ له رابط ثابت ويمكن إقامة Runs فيه.
- **Run:** جلسة جماعية من 4 جولات، لها preset ووقت بداية محفوظان؛ المراحل تُشتق من الوقت المعتمد ولا تحتاج بث عدّاد كل ثانية.
- **Round participation:** انضمام شخص لجولة بعينها؛ ينشئ Session شخصية محدودة بنهاية التركيز، ثم تُنهى عند تلك النهاية أو مغادرته/إيقافه قبلها.
- بعد انتهاء الجولات والاستراحة الطويلة يصبح Run مكتملًا وتعود شاشة Room إلى Lobby. إقامة Run آخر تحتاج Start جديدًا؛ لا دورة لا نهائية تحصد ساعات لحسابات غائبة. غياب الأعضاء لا يجعل Run يمتد؛ يمكنه إنهاء دورته المحددة ثم الانتظار، والروم تظل قابلة للاكتشاف ما دامت Open وغير مؤرشفة.

حالات Room: Open / Closed / Suspended / Archived. حالات Run: Lobby / Active / Completed / Cancelled. أثناء Active تُعرض المرحلة Focus / Short break / Long break من الخادم. حالات الشخص: Watching / Focusing / Paused personally / Break / Disconnected / Left / Removed. لا نخلط عضوية الروم بحالة الوقت.

إغلاق المالك يضع Room في Closed فورًا: تخرج من الدليل وتمنع دخولًا أو Run جديدًا، ويكمل الموجودون Run المحدد فقط؛ بعد نهايته تُنهى العضويات وتصبح الصفحة ملخصًا. التعليق الإداري Suspended يلغي Run فورًا عند حد الخادم ويغلق الفترات الحالية دون محو السابق. Archived للقراءة التاريخية فقط؛ الأرشفة التلقائية تشترط عدم وجود Run جارٍ أو عضوية ذات lease سارية ومرور 7 أيام منذ آخر نشاط معتمد، ولا تقطع Run مهما تأخرت أعمال التسوية.

## 4. الدخول وإنشاء الروم

الدليل العام يعرض العنوان والموضوع/الكورس واللغة والـ Preset والمرحلة وعدد الحاضرين، دون أسماء أو تقدم أشخاص. يمكن استكشاف الروم دون حساب؛ الانضمام والإنشاء يحتاجان حسابًا موثّق البريد/المزوّد، غير موقوف.

الإنشاء: Title من 3–60 حرفًا، وصف اختياري حتى 240 حرفًا، Language، Topic أو Approved library offering، preset، ثم معاينة ما سيظهر للعامة. لا روابط خارجية أو رفع ملفات في النصوص العامة أولًا؛ المحتوى نص عادي بعد التنقية. إنشاء الروم لا ينشر ملاحظات أو اسم مهمة خاصة.

يظهر اقتراح رومات مشابهة قبل الإنشاء. البداية بحد 3 رومات Open مملوكة للحساب وإنشاء روم واحدة جديدة لكل يوم UTC؛ يمكن للسياسة تعديل الحدود بتوثيق السبب. الحد يُطبق على الخادم ولا يُعاد بضبط المنطقة الزمنية. الروم غير المستخدم يُؤرشف بعد 7 أيام دون Run أو حضور؛ التاريخ الشخصي لا يُحذف. الوصول لروم مؤرشف يشرح الحالة ويقترح إنشاء/اختيار روم آخر.

روم الكورس يرتبط بعرض معتمد في المكتبة، لا بمنهج خاص يكشفه صاحبه دون نشر. الانضمام للروم لا ينشئ خطة أو Enrollment؛ يظل Join course إجراءً مستقلًا. اختلاف نسخ الكورس لا يمنع التركيز معًا، ولا يدمج لوحات المقارنة المختلفة.

صفحة ما قبل الانضمام توضح: «سيشاهد أعضاء الروم اسم العرض وحالة التركيز». **الظهور المحدود داخل الروم شرط مشاركة ظاهر**، وهو مستقل عن مشاركة التقدّم أو الظهور العام. من لا يريد هذا الظهور يختار Solo. الجمهور لا يرى قائمة الأعضاء، حتى لو كان اسم الروم عامًا.

الحضور النشط يكون في روم واحدة للحساب؛ تصفح الدليل لا ينقل الحضور. الانتقال لروم أخرى يعرض Leave and join، ويتحقق من سعة الجديدة وصلاحية الانضمام قبل إنهاء القديمة في معاملة واحدة؛ فشل النقل يبقي العضوية والوقت السابقين. الاشتراك في كورسات أو متابعة أشخاص لا يستهلك مقاعد رومات.

Watching داخل الروم لا يعمل بالتوازي مع مؤقّت Solo في v1. مع Solo يمكن استعراض الدليل والبيانات العامة فقط؛ الدخول يعرض Finish solo and join. ومن الروم يعرض Start solo: ينهي وقت الروم الحالي إن وجد ويغادر عضويتها ويبدأ Solo عند حد خادم واحد داخل معاملة ذرية. تُراجع جلسة Needs review صراحة قبل هذا التحويل؛ فشل قبول البديل يحافظ على الوضع السابق. لا نسخ لوقت الروم إلى Solo أو فقد للوقت الصحيح، ولا تتوقف ساعة الآخرين. الانتقال من Solo إلى عضوية الروم وحدها لا يبدأ وقتًا حتى Join round.

ينطبق إنهاء الوقت السابق على دخول روم مختلفة بعد انتهاء عضوية قديمة أيضًا؛ أما Rejoin لنفس الروم والجولة فيستعيد عرض Session القائمة دون إعادة بدء أو إهدار وقت. مساحة المقعد تعرض العدد المحجوز من 20 بما فيه من يعيد الاتصال، مع تمييزه عن عدد المتصلين حاليًا؛ لا نصف المقاعد المحجوزة بأنها أشخاص يتعلمون الآن.

## 5. السلوك أثناء الروم

| الموقف | السلوك الملزم |
|---|---|
| Lobby جديدة | المضيف يبدأ Run صراحة؛ بدء الروم لا يبدأ مؤقت كل الأعضاء بالنيابة عنهم |
| بداية Focus | يظهر Join this round؛ الوقت الشخصي يبدأ عند قبول الخادم، وليس عند فتح الصفحة |
| الدخول متأخرًا | يعرض الزمن المتبقي وخياري Join remaining time / Wait for next round؛ لا رصيد لما سبق الدخول |
| أقل من دقيقة متبقية | نرشّح الانتظار؛ يمكن الانضمام للباقي مع إظهار مدته الفعلية، دون احتساب جولة كاملة |
| الدخول أثناء Break | يستكشف الأعضاء؛ لا وقت تركيز حتى الجولة التالية وإقرار الانضمام إليها |
| Pause شخصي | يغلق الفترة الحالية، والروم تكمل؛ Resume يحتسب الباقي حتى نهاية الجولة الأصلية |
| نهاية Focus | يغلق الخادم Session عند الحد المحدد؛ الاستراحة لا تدخل الوقت ولا المنافسة |
| الجولة التالية | تتغير ساعة الروم تلقائيًا؛ يلزم Join this round مجددًا لبدء وقت الشخص، ولا يوجد حجز تلقائي مسبق |
| Leaving room | يغلق وقت الشخص عند قبول الخادم؛ يعرض ملخصه والرجوع للمهمة، ولا يؤثر على ساعة الآخرين |
| تبديل Work/Learning | إنهاء Session الحالية ثم بدء أخرى بالنوع الجديد، دون إعادة تصنيف الماضي |
| انتقال لصفحة أخرى داخل ديمة | تظل الجلسة الحالية مع شريطها؛ لا تُعد مغادرة الروم لمجرد التنقل |
| إغلاق المتصفح دون Leave | لا نعرف لحظة توقف العمل؛ الجولة تبقى محدودة بنهايتها، ولا تبدأ الجولة التالية تلقائيًا |
| تعطل الصوت/إشعار الموبايل | الساعة والحفظ يعملان؛ لا نعتمد على التنبيه أو Wake Lock لإغلاق الجولة |

في نهاية الجولة يظهر ملخص شخصي: الزمن المحفوظ وحالته، ومطلوبك المختار مع Worked on / Mark complete عند وجود مهمة. لا اختيار مسبق للإكمال. بطاقات الحضور تستخدم «Focusing» باعتبارها حالة معلنة، لا «تم التحقق من مذاكرته».

الروم صامتة في v1: لا ميكروفون أو كاميرا أو شات حر. النية المعروضة اختيارية ومن قائمة محايدة مثل Reading / Practice / Project / Work؛ اسم المهمة والملاحظات خاصان. تفاعل تشجيع محدود مثل Wave / Well done، بحد واحد كل 30 ثانية، يظهر بهدوء أثناء الاستراحة؛ لا وابل مؤثرات وسط التركيز.

## 6. المضيف والمغادرة والاعتدال

مالك Room يدير العنوان وإغلاق قبول أعضاء جدد والـ preset للـ Run القادم. مضيف Run يدير بدايته ويسلّم الدور لعضو يقبله. لا يملك أي منهما إيقاف عدادات الجميع أو تغيير مدة جولة جارية؛ هذا يمنع مفاجآت التحكم والتلاعب.

مغادرة المضيف لا توقف Run. يمكنه التسليم قبل المغادرة. عند غيابه دقيقتين دون مضيف بديل يستطيع عضو موثّق حاضر اختيار Take host؛ أول طلب ناجح ذريًا يأخذ الدور لهذا الـ Run فقط، ولا يصبح مالك الروم. عودة المضيف السابق لا تنتزع الدور تلقائيًا. إن لم يتطوع أحد، يكمل Run وقته ثم يعود للروم Lobby؛ يمكن لعضو حاضر تولي استضافة Run جديد بالإجراء نفسه. لا تعيين إجباري لأحد.

إثبات أهلية Take host يعتمد على lease اتصال مقبولة من الخادم وعضوية سارية، لا على ادعاء عميل عن غياب المضيف. تجديد lease كل 30 ثانية، والغياب بعد دقيقتين من آخر تجديد؛ عند فشل خدمة التحقق تُعطل المطالبة مؤقتًا بدل التخمين. هذه lease للتحكم فقط وليست دليل تعلم أو سببًا لخصم دقائق.

المضيف يستطيع Remove مع سبب ضمن قائمة، ويمنع العودة لنفس Run؛ مالك الروم يستطيع حظرًا من رومه، ومشرف المنصة يراجع البلاغات ويوقف الروم/الحساب عند اللزوم. كل قرار مؤثر له سجل. المضيف لا يرى ملاحظات أو جلسات خاصة ولا يحرر أرصدة الناس.

Remove إجراء صريح ينهي عضوية الشخص وفترته الجارية الخاصة بالروم عند وقت الخادم؛ يظل السابق محفوظًا ويُعرض Start solo اختياريًا. يختلف عن انتهاء lease الاتصال الذي لا يثبت توقف الشخص عن العمل ولا يمحو وقته.

Report room / Report participant / Block متاحة من قائمة واضحة. Block يخفي بيانات الطرفين وتفاعلاتهما في العرض الشخصي ويمنع المتابعة؛ لا يَعِد بإخفاء وجود الطرف الآخر عن كل العالم أو بإخراجه من روم عامة. تعرض الواجهة خيار Leave أو اختيار روم أخرى. تعليق روم بسبب إساءة يوقف قبول المشاركين ويغلق مشاركاتها عند وقت إجراء الخادم، مع حفظ الوقت السابق الصالح.

## 7. انقطاع الاتصال والأهلية

المبدأ السابق قائم: Start/Resume المقبولان مصدرهما الخادم؛ Offline Stop تصحيح شخصي للفترة المتأثرة، لا وقت تنافسي موثوق من ساعة المتصفح. الفترات المغلقة سابقًا تحتفظ بأهليتها. إعادة طلب فقد الرد تسترجع نتيجة نفس العملية قبل تصنيفه Offline.

الجولة الجديدة لها نهاية مسجلة مسبقًا. إذا انتهت عند هذا الحد قبل أي إيقاف محلي مبكر، يكون الحد صالحًا حتى لو تأخر التنفيذ المجدول. أما وصول تصحيح Offline Stop يؤكد توقفًا أبكر، فيراجع الفترة المتأثرة وفق سياسة التصحيح، ولا يسمح بتحويلها لوقت مؤهل عبر تجاهل قصد الإيقاف المسجل.

Realtime انقطع و HTTP يعمل: تظهر Reconnecting، نقرأ snapshot بإصدارها؛ يمكن إتمام أمر عبر HTTP بعد التحقق وتجديد lease. انقطع الاثنان: العداد المحلي تقديري، والبدء/الاستئناف/الانضمام لجولة جديدة معطل؛ نحتفظ بقصد الإيقاف. الـ lease واحدة تتجدد عبر طلب معتمد كل 30 ثانية من جهاز الحساب المتحكم بالحضور؛ تبديل هذا الجهاز يتطلب انتقال تحكم صريحًا يمنع طلبات الجهاز القديم.

| منذ آخر تجديد lease مقبول | الأثر |
|---|---|
| أقل من 90 ثانية | عضو متصل في العرض، ومقعده محجوز |
| 90 إلى أقل من 120 ثانية | يظهر Reconnecting؛ المقعد محجوز ولا نخصم وقتًا |
| 120 إلى أقل من 180 ثانية | يحق لعضو مؤهل طلب المضيف وفق الشروط؛ المقعد ما زال محجوزًا |
| 180 ثانية أو أكثر | Membership تصبح Expired ويُحرر المقعد؛ تُمنع قراءة roster الخاصة فورًا، ولو لم ينفذ Cron |

عودة الاتصال قبل 180 ثانية تجدّد نفس العضوية إن لم يُزل الشخص أو تغلق الروم. بعد انتهاء العضوية يلزم Rejoin معلن وفحص سعة جديد؛ إذا امتلأت الروم يعرض Room full دون طرد أحد أو استعادة مقعد قسرًا. لا تستعيد العودة دور مضيف نُقل بالفعل.

**تحرير المقعد لا ينهي Session المقبولة أو يسحب أهلية وقتها**: تظل محدودة بنهاية الجولة المعروفة، ويمكن لصاحبها رؤيتها وإيقافها من سجل الوقت الشخصي دون أي roster أو بيانات أعضاء. تعرض «تم تحرير مقعدك؛ جلستك الحالية محفوظة حتى حدها» مع Rejoin أو Finish and start solo. عند Rejoin لا تتكرر Session القائمة؛ إن كانت الجولة انتهت لا يبدأ أي وقت جديد. فشل التجديد لا يمنح جلسة جديدة ولا يلغي شرط عدم الازدواج.

عند الرجوع نقرأ server time و Room/Run/Session versions؛ لا نعيد تشغيل ما انتهى، ولا نعوض الجولات الفائتة بوقت. تعديل ساعة الجهاز لا يغيّر الرصيد. إذا استلم جهاز آخر التحكم، تُرفض أوامر الجهاز القديم حتى يعيد الاستلام الصريح. لا يُخفى تضارب الوقت وراء نجاح بصري.

| RoomRun | room، host، immutable preset snapshot، started_at، completed/cancelled_at، version |
| RoundParticipation | user، run، round index؛ فريد لكل شخص/جولة؛ ترتبط به Session واحدة أو أكثر دون تداخل |
| TimeSession / Interval | نفس سجل الوقت المركزي، مع source Solo/Room/Open، cap/end boundary/control version |
| RoomReport / ModerationAction | هوية المبلّغ محمية، سبب وقرار وأثر، وسياسة احتفاظ موثقة |

أوامر `/api/v1/rooms`: Create، Join/Rejoin، RenewPresence، Leave، StartRun، JoinRound، TransferHost، ClaimHost، Close، Report، Remove. أمر SwitchFocusMode ينفذ التحويل الذري بين الروم والفردي. أوامر الوقت المركزية Pause/Resume/Finish لا تنسخ بمنطق مختلف للروم. كل تعديل يحمل operationId و expectedVersion، ويتحقق من الهوية والملكية/الدور داخل المعاملة.

Room تحفظ المضيف الحالي في Lobby أيضًا؛ يُنسخ إلى Run عند Start. ClaimHost في Lobby تتبع مهلة الغياب والأهلية نفسها، فلا يصبح فتح Run جديد متوقفًا للأبد على رجوع المالك. Close من المالك يغلق قبول أعضاء جدد وينتظر نهاية Run الجاري؛ الإغلاق الفوري قبل النهاية صلاحية اعتدال مشرف المنصة.

JoinRound يتحقق في معاملة واحدة من: عضوية سارية، سعة الروم، مرحلة Focus الحالية، عدم الحظر، الموافقة على الظهور، وعدم وجود Session نشطة للحساب. ينشئ Session بحد أقصى = أصغر نهاية الجولة والسقف العام. سباق انضمام غرفتين ينتج نجاحًا واحدًا، ورد Conflict يربط بالجلسة الموجودة.

Finish ثم العودة لنفس الجولة ينشئ Session جديدة تحت المشاركة نفسها بوقت البداية الجديد؛ لا يعيد فتح Session منتهية ولا يعوض الفجوة. نهاية المرحلة تنهي Session الموقوفة شخصيًا أيضًا، مع مجموع فتراتها الفعلية، حتى لا يبقى قفل Paused يمنع الجولة التالية.

نهاية الجولة تُطبّق عند أي قراءة/أمر يحتاجها وبعمل تسوية دوري آمن؛ التاريخ يُغلق عند الحد المخزن لا وقت وصول Cron. ليس إغلاق مؤقت JavaScript أو استمرار العملية في ذاكرة السيرفر ضمانًا للحفظ. حذف الحساب يوقف العضويات والوقت عند حد الخادم ويعيد توزيع دور المضيف؛ لا يحذف سجلات الآخرين.

ترتيب التسوية داخل معاملة قبل Join/StartRun/Archive أو snapshot: إغلاق الفترات التي بلغت حدها، ثم إنهاء Run عند planned_end، ثم انتهاء العضويات حسب lease/إغلاق Room، ثم حساب المقاعد والأهلية والأرشفة. Closed بعد نهاية Run لا يعود Lobby مفتوحة تلقائيًا؛ Open فقط تعود Lobby وتظل قابلة للاكتشاف. آخر نشاط للأرشفة = أحدث إنشاء/تجديد حضور/بدء Run/نهاية Run معتمدة لا تتجاوز الآن. يُمنع وجود أكثر من Run جارٍ للروم بقيد ومعاملة؛ التكرار لا يغير الحدود التاريخية أو يعيد Run مكتملًا. العمل الدوري يزيل السجلات العالقة، لكن شروط الوقت والصلاحية والمقاعد تُحسب عند الطلب حتى لو توقف العامل.

إسقاط الدليل العام منفصل عن snapshot الأعضاء. بيانات الأعضاء تُقرأ عبر API مصرح لكل طالب، مع تطبيق الخصوصية والحظر. لا وصول إلى بريدهم أو مهامهم الخاصة. **لا ننشر أسماء أو تقدّم أو قوائم أعضاء داخل broadcast جماعي**؛ أحداث الروم تحمل phase/version/count فقط. بعد Remove تُرفض قراءة snapshot خاصة فورًا، حتى لو بقي socket قديم متصلًا مؤقتًا.

## 9. Realtime والبنية الحالية

نستخدم Supabase Realtime للإشعار بتغير الإصدار/المرحلة، والخادم وقاعدة البيانات مرجع الحقيقة. القنوات الخاصة لها تحقق عضوية، وطلبات تعديل الساعة من العميل لا تُقبل بمجرد وصول Broadcast. النصوص المعروضة من مصدر الخادم المنقّى، لا payload يختاره مشارك. Supabase يدعم صلاحيات Broadcast/Presence عبر RLS ويحسبها عند الانضمام للقناة؛ لذلك لا نعتمد على بقاء الاشتراك وحده كترخيص دائم لقراءة بيانات الأعضاء. [Authorization](https://supabase.com/docs/guides/realtime/authorization).

الحدود الرسمية لـ Free وقت البحث: 200 اتصال متزامن، 100 رسالة/ثانية، و 20 Presence message/ثانية. الرسائل المرسلة والمسلّمة لها أثر؛ توزيع حدث واحد على أعضاء كثيرين ليس كلفة رسالة واحدة فقط. لذلك لا نبث ticks كل ثانية، ولا نستخدم Presence لإثبات العمل. [Realtime limits](https://supabase.com/docs/guides/realtime/limits).

الحصة الشهرية لـ Free هي 2 مليون رسالة Realtime؛ الوصول للسعة المتزامنة لا يعني أن الاستخدام الشهري مناسب. نراقب الحصة ونتوقع نهاية دورة الفاتورة من الاستهلاك الفعلي، مع إنذار عند 70% وإعادة تقييم قبول Runs جديدة عند توقع التجاوز؛ لا ترقية مدفوعة تلقائية. [Realtime pricing](https://supabase.com/docs/guides/realtime/pricing).

**بوابة التجربة التقنية:** حد تجريبي إجمالي 100 اتصال Realtime، لا 100 شخص؛ 100 شخص قد يستهلكون اتصالات أكثر. نختبر 4 رومات × 20 عضوًا مع 20 اتصال جهاز ثانوي لمدة ساعتين، ثم تنوع توزيع نفس الحمل على الرومات. يجمع العميل اشتراكاته في اتصال واحد قدر الإمكان؛ التنقل لا ينشئ اتصالًا مهجورًا. مراقبة الاتصالات والقبول يجب أن تحفظ احتياطي حدود المزوّد. هدف الاختبار: p95 لتأكيد الانضمام/بدء الوقت ≤2 ثانية في الظروف المحددة، اتفاق عرض المرحلة في ≤2 ثانية، صفر جلسات مزدوجة، وصفر تسريب أسماء بعد فقد الصلاحية. تُسجل شبكة الأجهزة والمنطقة وحمل الخادم؛ هذه أهداف وليست أداءً تم إثباته.

نقيس الرسائل الفعلية والفان آوت والاتصالات وCPU/ذاكرة Workers وحصة الشهر، مع سيناريو انتقال جولات متزامن وإعادة اتصال جماعية. نجمّع تحديثات الدليل ونقلل طلبات الخلفية؛ لا نخفض اتساق الوقت لتمرير اختبار السرعة. عند قرب حد السعة تُمنع انضمامات جديدة برسالة صادقة واختيار روم أخرى/تركيز فردي، مع إبقاء الجلسات المقبولة قابلة للإنهاء. الجمهور المتوقع50–100 مستخدم لا يحدد وحده عدد الاتصالات المتزامنة.

إذا لم يتحقق الهدف ضمن Cloudflare Workers Free/Supabase Free، لا نعلن اكتمال الجماعي أو ننشره بمزامنة غير موثوقة. يُراجع التنفيذ أوحجم التجربة أو مورد التشغيل بتكلفة معلنة وموافقة مستقلة قبل أي ترقية. [ARCHITECTURE_AND_DATA](ARCHITECTURE_AND_DATA_AR.md) يحدد البنية الحالية وتشغيل التسوية ضمن الميزانية؛ لا توجد أعمال مجدولة أو خدمات جديدة تم إعدادها بهذه الوثيقة.

المسارات: `/app/focus` للفردي ومدخل الرومز، `/app/rooms` للدليل، `/app/rooms/new` للإنشاء، `/app/rooms/:roomId` للمشاركة. Course → People يعرض رومات الكورس؛ العودة من الروم تحفظ سياق المهمة دون نقل بياناتها الخاصة إلى الروم. التنقل الأساسي للمنصة يظل Today / My Plan / My Courses / Focus / Progress / Library.
