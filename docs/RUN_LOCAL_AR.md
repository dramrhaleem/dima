# تشغيل ديمة محليًا

هذه بيئة تطوير محلية. Google OAuth مهيأ على هذا الجهاز في وضع Testing؛ بقية الخدمات محلية وليست إعداد إنتاج. تحتاج Node المحدد في `.nvmrc` وpnpm المحدد في package.json وDocker Engine مع Compose. اختبارات المتصفح تستخدم Chrome الموجود؛ يمكن تحديد مساره عبر `DIMA_CHROME_PATH`.

## أول تشغيل على جهاز ذي مساحة كافية

من جذر المشروع:

```bash
pnpm install --frozen-lockfile
pnpm backend:start
pnpm test:backend
pnpm configure:local
pnpm configure:learning
pnpm configure:time
pnpm check
pnpm build
pnpm build:client
```

الأمر `test:backend` ينشئ/يجدد حسابات اختبار صناعية خارج Git، وهي لازمة لاختبارات API والمتصفح اللاحقة. بيانات التجربة تبقى في Docker volume مستقل. `configure:local` ينشئ إعدادات localhost فقط، ويرفض الكتابة فوق ملف مختلف موجود؛ لا تطبع هذه الملفات أو تنسخ مفاتيح مشروع آخر.

شغّل كل أمر من التالي في terminal منفصل:

```bash
pnpm preview:worker
```

```bash
pnpm --filter @dima/client-proof preview
```

- اللاندنج: `http://127.0.0.1:8787`، الحساب `/auth`، وفحص B0 `/dev/foundation`.
- بريد التطوير الملتقط: `http://127.0.0.1:54325`؛ OTP لا يرسل إلى بريد خارجي. لا تستخدم بيانات حساسة.
- نفس واجهة React ببناء مستقل: `http://127.0.0.1:4174`.
- يمكن إنشاء حساب اختبار من الواجهة؛ كلمات المرور للاختبار فقط، بلا بيانات حقيقية. تسجيل الدخول في B0 في الذاكرة، فيحتاج إعادة الدخول عند reload بينما السجل محفوظ في PostgreSQL.
- للتطوير السريع في Next يمكن تشغيل `pnpm dev` على المنفذ 3000. هذا ليس بديلًا عن اختبار workerd.

بعد جاهزية الخادمين:

```bash
pnpm test:api
pnpm test:accounts
pnpm test:learning
pnpm test:recovery
pnpm test:time
pnpm test:browser
node scripts/measure-local.mjs
```

الاختبار الأخير يقيس زمن استجابة محليًا؛ لا يثبت CPU Cloudflare أو سعة الإنتاج. ملف النتائج يصرّح بهذا الحد.

## إعداد هذا الجهاز محدود المساحة

عند تنفيذ B0 كانت المساحة الحرة على قرص النظام نحو 1.4GB، لذلك حُفظ store الاعتمادات على Data2، دون تغيير إعداد pnpm العام أو حذف بيانات المستخدم. لإعادة التثبيت هنا استخدم:

```bash
pnpm install --frozen-lockfile --store-dir /media/amro/Data2/dima-local-runtime/pnpm-store --virtual-store-dir /media/amro/Data2/dima-local-runtime/dependencies/virtual-store
```

الملف المحلي المتجاهل `.local/worker-build.json` يوجه `pnpm build` إلى mirror مملوك للمشروع على Data2، بعلامة ملكية وبصمة مدخلات. داخل mirror الاعتمادات ضمن جذر البناء، لأن external virtual-store خارج tracing root كسر تجميع OpenNext. `preview:worker` يتحقق من تطابق المدخلات قبل التشغيل. عند تغير ملفات التطبيق أعد `pnpm build`.

على جهاز عادي أو CI لا يوجد هذا الإعداد: نفس الأمر يبني مباشرة داخل المستودع. النسخة المعزولة ناتج توليد وليست مرجع تعديل؛ عدّل المصدر هنا فقط. لا تغيّر tracing root إلى جذر النظام ولا تعدّل مكتبات node_modules يدويًا.

Data2 بنظام NTFS؛ قاعدة PostgreSQL والأسرار تحتاج صلاحيات POSIX ولذلك بقيت في volume خاص على Linux و`~/.local/state/dima-b0` بصلاحيات مقيدة. ملفات mirror التي تُنسخ للتجربة تحوي إعدادات عامة محلية والـanon key فقط، ولا توقيع JWT أو كلمة مرور DB أو حسابات الاختبار. Docker يحتاج مساحة محلية لبياناته؛ لم يُعد إعداد daemon أو تُنقل مشروعات أخرى.

## الإيقاف وإعادة التشغيل

أوقف terminal الويب والعميل بـCtrl+C ثم:

```bash
pnpm backend:stop
```

هذا يوقف خدمات ديمة ويحفظ البيانات؛ لا يحذف volume أو حسابات الاختبار. لإعادتها `pnpm backend:start` ثم أمرَي preview. راجع [تفاصيل الباك إند](../scripts/local-backend/README.md).

## قبل الانتقال إلى خدمات بعيدة

إعداد Supabase المستضاف وCloudflare الفعلي وDNS وSMTP الإنتاجي والنشر العام لم تُنفذ. Google OAuth المحلي تحقق في B1 وفق دليله. `.github/workflows/ci.yml` إعداد محلي لم يُشغّل على GitHub، ولا يوجد deploy تلقائي فيه. تبقى probe معطلة افتراضيًا عند غياب متغير التفعيل، ويجب إزالة endpoints والجدول التجريبي قبل B7.

## Google وحالة B1

تقرأ خدمة Auth ملف Google الخاص خارج المشروع إن وجد؛ ملف `google.env` بصلاحية0600 داخل runtime الخاص. يحتوي بيانات عميل محلي مصرح، ولا يُنسخ إلى بيئة الويب أو Git. الجهاز الجديد يعمل بالبريد المحلي دون هذا الملف وGoogle غير مفعّل. `DIMA_GOOGLE_ENABLED` في بيئة الويب علم عام فقط، ولا يكفي لتفعيل المزود وحده.

الحساب الفعلي B1 بجلسة HttpOnly مستمرة؛ وصف ذاكرة الجلسة أعلاه يخص probe B0 فقط. إعدادات `.env` الحالية تحتوي Google enabled، لذلك قد يرفض configure:local الكتابة عليها لأنها تختلف عن قالب البريد فقط؛ هذا مقصود للحفاظ على الإعداد. لا تعاود configure عند إعادة تشغيل مشروع مجهز.

البريد المحلي يتطلب Mailpit وخادم قالب صغير؛ start يشغل صورًا مثبتة، ويطبّق migrations جديدة بالترتيب داخل معاملات دون مسح بيانات. OTP جديد يؤكد البريد، ولم يعد autoconfirm هو إعداد Auth المحلي.

## كاتب بيانات B2 المحلي

`backend:start` ينشئ مفتاح دور الخادم في `~/.local/state/dima-b0/server.env` بصلاحية 0600. أمر `configure:learning` يضيفه إلى إعدادات خادم الويب المحلية فقط، ويحافظ على إعداد Google الموجود. لا يصل إلى Vite أو NEXT_PUBLIC أو متصفح المستخدم.

معاينة Workers تقرأ قائمة متغيرات محددة من `.local/worker-preview.env` بصلاحية 0600 عن طريق `--env-file`. ملف الأسرار يبقى على نظام ملفات المشروع الذي يدعم صلاحيات POSIX، ولا ينسخ إلى مرآة البناء الموجودة على Data2. اختبارات المعاينة لا تعني إعداد Workers المستضاف.


## التحقق من B3

`test:recovery` ينشئ حسابات اصطناعية جديدة على localhost فقط، ويختبر توافق B2 وحفظ العمل الجزئي والمثبتات والتراجع وتعارض الأجهزة. مساعد الأيام التاريخية يقبل فقط مستخدمي اختبار باسم `b3-…@example.test`؛ ليس route في التطبيق ولا تجاوزًا لساعة الإنتاج. اختبارات المتصفح تحتاج الباك إند الحقيقي نفسه. لا تعاد تهيئة بيانات حساب المستخدم.

## تشغيل مهام الوقت في B4

`backend:start` يطبّق migration سجل الوقت بالترتيب، داخل معاملة، دون إعادة ضبط قاعدة البيانات. `configure:time` ينشئ مفتاحًا خاصًا في `~/.local/state/dima-b0/jobs.env` ويضيفه إلى إعدادات خادم الويب المحلية فقط، مع الحفاظ على إعداد Google. الملفات بصلاحية 0600؛ لا تنسخها إلى المتصفح أو مرآة البناء أو Git.

بعد بناء المصدر وتشغيل معاينة Workers، يمكن تنفيذ دفعة واحدة:

```bash
pnpm jobs:once
```

ولتسوية المهام المستحقة باستمرار أثناء التطوير، شغّل في terminal مستقل:

```bash
pnpm jobs:local
```

هذا مشغّل محلي كل 30 ثانية، وليس خدمة نظام أو إعداد جدولة للإنتاج. أوقفه بـCtrl+C؛ `backend:stop` يوقف كذلك المشغّل المملوك لهذا المشروع. لا تشغّله أثناء اختبارات سباق jobs التي تحتاج تحكمًا صريحًا في وقت التنفيذ.

تُحفظ نهاية الفترة في قاعدة البيانات عند بدايتها؛ تأخر المشغّل لا يمدد الوقت المحتسب. قراءة المستخدم لحالته تسوّي كذلك فترته المستحقة. إعداد الجدولة المستضافة ومراقبة تراكم المهام يظلان ضمن تحقق B7.
